# Connection-Map — 연결 3D

오픈웹(위 판)과 다크웹(아래 판)을 겹쳐 그리고, 두 층 영토 사이 연결을 선으로 잇는 3D 화면이다.
생태계 지도 설계서 4.4 「연결 3D」 를 따른다. 닥스훈트(오픈웹)와 다크초코(다크웹)가 같이 쓰는 저장소다.

    처음 만든 때   2026-10-04 다크초코 (시제품)
    상태          시제품. 다크웹 판은 실제 자료로 그리고, 오픈웹 판 · 연결선은 가짜 자료로만 그려 봤다
    맡은 쪽       역할 나누기는 두 팀이 정한다

## 여는 법

빌드 단계가 없다. 파일 셋(`index.html` · `main.js` · `lib.js`)과 three.js(CDN, 판 고정)로 돈다.

```
python -m http.server 3004          # http://localhost:3004  — 통합 Supabase 설정(data/supabase.json)은 저장소에 들어 있다
npm test                            # 계산 시험 (node --test, 설치할 것 없음)
```

배포 주소는 GitHub Pages(main · 루트)다. 다른 Supabase 프로젝트를 보려면 `data/supabase.json` 의 주소와 공개 열쇠만 바꾼다.

| 주소 뒤에 | 무엇 | 없으면 |
|---|---|---|
| `?dark=<주소>` | 다크웹 배치 결과 파일(아래 칸 꼴) | 통합 Supabase 표 `public.dark_layout` (설정 `data/supabase.json`). 설정도 없으면 `./data/dark-layout.json` |
| `?dark=supabase` | 꼭 표에서 읽는다 | — |
| `?open=<주소>` | 오픈웹 배치 결과 파일 | 위 판은 빈 원판 |
| `?links=<주소>` | 연결 줄 목록 파일(JSON 배열) | 통합 Supabase 공개 뷰 `links_public`. 뷰가 없거나 공개 읽기가 안 열렸거나 켜진 줄이 없으면 연결선 없이 그리고 「연결 자료 없음」 |
| `?links=supabase` | 꼭 공개 뷰에서 읽는다 | 설정 파일이 없으면 멈춘다 |

**통합 Supabase 는 공개 열쇠로만 읽는다**(apikey 머리글만 — 익명 역할). 설정 파일의 주소는
`https://<프로젝트>.supabase.co` 꼴만 받는다 — 열쇠가 다른 곳으로 가지 않게. 설정 파일이 **없으면** 위 표대로
넘어가고, **있는데 꼴이 틀리면** 넘어가지 않고 까닭(열쇠 값은 안 적는다)을 적고 멈춘다.

## 공개 저장소에 넣지 않는 것

이 저장소는 공개다.

- **공개 열쇠 하나만 넣는다**(아래 「공개 열쇠」). 비밀 열쇠 · 쓰기 열쇠는 넣지 않는다 — 쓰기 열쇠는 각 팀 배포 비밀값에만 있다.
  `data/` 안에서는 `data/supabase.json` 하나만 저장소에 들어가고(.gitignore), 시험 13 이 그 파일에 공개 열쇠(`sb_publishable_`)만 있는지 본다
- **기업명 · 피해 조직명을 넣지 않는다**(2026-10-02 협업 회의 결정). 시험과 예시는 지어낸 이름만 쓴다
- 원본 DB 덤프 · 실제 배치 결과 파일을 넣지 않는다. 화면은 실행할 때 공개 표 · 뷰에서 받는다

## 공개 열쇠 (2026-10-06 결정)

`data/supabase.json` 에 통합 Supabase(link-3d)의 주소와 **공개 열쇠(publishable)** 를 넣어 둔다. 처음에는 공개 열쇠도 저장소 밖에
두었는데, 그러면 저장소를 받아 열거나 Pages 로 배포했을 때 다크웹 판이 비어 보여서 넣기로 했다.

- 공개 열쇠는 원래 웹 화면에 실려 누구나 보는 값이다. 무엇을 읽고 쓸 수 있는지는 열쇠가 아니라 DB 의 권한이 정한다
- 이 열쇠 하나로 읽히는 것은 공개용으로 만든 표 · 뷰뿐이다 — 3D 다크웹 판 표 `dark_layout` · 연결 공개 뷰 `links_public`, 그리고
  같은 프로젝트의 가이드라인 사이트가 공개로 내는 표. 원본 표(`links` 원본 줄 · 다크웹 원본 스키마)는 못 읽고, 쓰기는 모두 막혀 있다
  (2026-10-06 공개 열쇠로 확인: 원본 401 · 42501, 공개 뷰 쓰기 401 · 42501)
- 열쇠를 바꿀 때는 Supabase 대시보드 Project Settings → API Keys 에서 새 공개 열쇠를 만들어 이 파일을 바꾸고 옛 열쇠를 지운다

## 무엇을 그리나

- **다크웹 판은 다크웹 지도가 계산해 표에 올린 칸 위치를 그대로 그린다.** 배치를 여기서 다시 계산하지 않는다. 2D 다크웹
  지도와 영토 모양 · 크기가 같아야 해서다. 칸 하나가 육각 기둥 하나다
- **섬은 가운데가 높게 쌓인다 — 평평한 층 세 단으로.** 섬 칸들의 무게중심에서 멀수록 한 단씩 낮다. 단은 넓이로 나눠
  섬마다 세 단이 비슷한 넓이를 갖는다. 데이터와 상관없는 표시 규칙이다(설계서 3.5). 층 높이는 `lib.js` `H_TIERS`
  — 칸 반지름의 0.3 · 0.8 · 1.4 배(2026-10-07 피드백 「경사면이 그물처럼 보인다」 로 매끈한 경사에서 바꿨다. 피그마
  「③-0 기본 · 원형 판넬 · 쌓인 블록」 화면 PNG 에서 칸 너비 대비 옆면 높이를 쟀다. Figma 원본 값이 아니다)
- 영토 사이 선은 2D 와 같은 자리(이웃 칸이 다른 영토이거나 빈 변)에 긋는다
- 두 판은 같은 크기의 원형이다. 크기는 더 큰 쪽 배치에 맞춘다
- **두 판 사이 높이는 판 반지름의 1.8 배다**(`lib.js` `GAP_RATIO`, 2026-10-07 피드백 「원판 간격 넓히기」 — 전에는 0.9 배).
  피그마 「③-0」 화면 PNG 에서 잰 비율이다(Figma 원본 값이 아니다). 카메라는 기울기 30° 고정으로 두 판 둘레가 화면 끝에서 6% 안에 다 들도록 거리를 맞추고
  위아래 여백을 같게 한다(`fitCamera`, 원근 투영을 그대로 계산). 화면 폭이 좁으면 폭에 맞춘다

## 동작 (설계서 4.4)

| 하면 | 되는 것 |
|---|---|
| 처음 | 회전 160°, 연결선 숨김, 패널 접힘 |
| 빈 곳 좌우 끌기 · 오른쪽 아래 슬라이더 | 0 ~ 360° 회전. 기울기는 고정 |
| 영토 누르기 | 그 영토와 반대쪽 층에서 이어진 영토만 높이를 지키고 나머지는 바닥으로 내려가며 흐려진다. 두 영토 사이 선이 오픈웹 판 아래에서 내려와 다크웹 영토에 닿는다. 연결이 없으면 「다른 층과 연결 없음」. 패널이 펼쳐진다 |
| 섬 이름 누르기 | 그 섬 전체를 진하게, 그 섬에서 반대쪽 층으로 가는 연결만 |
| 같은 것을 다시 누르기 · 빈 곳 누르기 · Esc | 고르기 풀기 |
| 찾기 | 두 판 영토 이름에서 찾는다. 고르면 3D 안에서 그 영토를 고른다 |

패널은 개요 · 사건 · 연결 세 탭이다. 연결 탭은 영토면 반대쪽 영토 목록(관계 유형 · 신뢰도), 섬이면 반대쪽 섬마다
건수다. **사건 탭은 비어 있다** — 배치 결과에 사건 칸이 없다. 무엇을 보일지는 두 팀이 정한다.

## 받는 자료

**받은 값은 데이터로만 쓴다.** 글자는 `textContent` 로만 넣고 `innerHTML` 에 자료를 넣지 않는다. 색은 `#RRGGBB`
꼴만 받는다. 영토 번호 · 이름 · 섬 코드가 틀린 줄, 같은 번호가 겹친 줄, 쓸 칸이 하나도 안 남은 줄은 버리고 몇 줄
버렸는지 위에 적는다. 정수가 아닌 칸과 다른 영토와 겹친 칸은 그 칸만 뺀다(`lib.js` `parseLayout`).

### 다크웹 판 — 표 `public.dark_layout`

다크웹 지도(다크초코)가 배포할 때마다 표를 통째로 새로 바꾼다(하루 두 번 예약 · 데이터 갱신 신호 · 손 배포). 영토 한 줄에
칸 위치 목록이 들어 있다. 칸 위치는 판마다 바뀔 수 있으니 저장해 두지 말고 열 때마다 읽는다.

| 칸 | 뜻 |
|---|---|
| `territory_id` | 영토 번호(소문자 · 숫자 · `-`). 이름이 그대로면 바뀌지 않는다. 연결 줄이 이것을 가리킨다 |
| `web` | `dark` |
| `island_id` · `island_name` | 섬 코드(`FORUM` · `RANSOMWARE` · `TELEGRAM` · `ACTOR`) · 이름 |
| `territory_name` | 영토 이름. 가해 쪽 이름(포럼 · 랜섬웨어 그룹 · 텔레그램 채널 · 행위자 핸들)뿐이다 |
| `aliases` | 별칭. 다크웹은 늘 비어 있다 |
| `kind` | 영토 종류(포럼 · 랜섬웨어 그룹 · 텔레그램 채널 · 행위자) |
| `cells` | 칸 위치 `[[q, r], ...]` — 뾰족 위 육각 axial 좌표 |
| `color` | 섬 색 `#RRGGBB` |
| `quarter` · `as_of` | 이 배치의 분기 · 자료 시각(UTC 로 온다 — 화면은 한국 시각으로 바꿔 적는다) |

칸 가운데는 `x = s·√3·(q + r/2)`, `y = s·1.5·r` 이다(`s` 는 칸 반지름). 이웃 여섯은 `[q+1, r]` · `[q+1, r-1]` ·
`[q, r-1]` · `[q-1, r]` · `[q-1, r+1]` · `[q, r+1]` 이다.

### 오픈웹 판

**꼴은 닥스훈트가 정한다**(2026-10-06). 두 판은 연결 DB 로 잇는다. 지금 시제품은 `?open=` 으로 다크웹 판과 같은 칸 꼴
파일을 받아 그린다. 오픈웹 꼴이 정해지면 그것을 읽게 고친다. 3D 가 오픈웹 쪽에서 받아야 하는 것은 셋이다 — 바뀌지
않는 영토 번호(연결 줄이 가리킨다) · 영토 이름과 섬 · 영토 모양(칸 위치, 또는 2D 오픈웹 지도의 배치를 다시 그리는 방법).

### 연결 — 공개 뷰 `links_public`

원본 표 `public.links` 는 공개 열쇠로 못 읽는다. 공개 뷰에는 **DB 반영이 켜진 줄만** 나오고, 피해 조직 · 근거 · 설명 ·
일치 항목처럼 이름이나 주소가 섞일 수 있는 칸은 없다. 뷰는 공개 열쇠로 읽기만 된다.

| 칸 | 뜻 |
|---|---|
| `link_id` | 연결 번호(`LNK-0001` 꼴) |
| `rel_type` | 관계 유형 — `SAME_DATASET` · `REPOST` · `SAME_CONTENT` · `SOURCE_CLAIM` · `SAME_ACTOR` · `CONTACT_MATCH` · `PROMOTION_OF` |
| `direction` · `verify_status` · `confidence` · `match_scope` | 관계 방향 · 검증 상태 · 신뢰도(상 · 중 · 하) · 일치 범위 |
| `dark_island` · `dark_territory` | 다크웹 섬 · 영토 |
| `open_island` · `open_territory` | 오픈웹 섬 · 영토 |
| `dark_observed_at` · `open_observed_at` | 양쪽 관측 시각 |
| `event_id` · `finding_id` | 다크초코 사건 번호(`LEAK-n`) · 오픈웹 발견 건 번호 |

시제품은 `dark_territory` · `open_territory` 를 영토 번호나 이름 어느 쪽으로도 맞추고, 양 끝이 다 맞아야 선이 된다.
이름은 바뀔 수 있으니 **영토 번호를 넣기를 권한다.** 뷰가 없을 때(404 · PGRST205 · 42P01), 공개 읽기가 안
열렸을 때(42501), 켜진 줄이 없을 때는 오류가 아니라 「연결 자료 없음 — 까닭」 으로 적고 선 없이 그린다. 틀렸거나
거둔 열쇠 같은 그 밖의 401 · 403 은 오류로 적는다. 오픈웹 판이 없으면 줄 수만 적고 선은 긋지 않는다.

## 협업 규칙 (D4rkn3ttz-Collaboration)

- 가지는 `feature/영문` 으로 판다. main 에 바로 올리지 않는다
- 커밋 제목은 「작업명_번호」(예: `3D연결시제품_1`)
- PR 은 다른 팀 공동작업자 1명이 확인한 뒤 머지한다(급하면 예외). 올린 쪽이 혼자 머지하지 않는다
